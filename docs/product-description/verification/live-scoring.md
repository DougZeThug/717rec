# Verification: live scoring

How to run this file: this is the hardest file in the directory to run and the
one that matters most, because almost none of it was reachable by the automated
pass. It needs **two real devices, two real accounts, and a real match**.

Before you start, arrange:

- A **throwaway match** in the active season with both teams assigned and no
  result. Every write here is a real write to the real league: never run these
  items against a match that counts.
- A **player** account with an **approved** membership of team A, and a **second
  scorer** — a different account with an approved membership of team B, on a
  **second physical device**. A second tab in the same browser shares the session
  and will hide exactly the bugs these items are looking for.
- An **admin** account, for the reopen items and for the permission items.
- A **real phone**, because live scoring is the one part of 717rec designed
  phone-first, and for the offline items. Use **aeroplane mode**, not the devtools
  offline toggle: the toggle stops ordinary requests but does not drop the open
  realtime websocket the way losing signal does, which is the whole point of the
  offline items here.

Work a match through in order — start, set up, enter rounds, correct one, finish
a game, finish the match — and take the items as you reach each stage, rather than
jumping about. Several items deliberately leave the match in an odd state (won but
not ended, decided but not saved); the next item usually depends on it. When you
have finished, either save the result or ask an admin to reopen and tidy the
match, so the league is not left with a half-scored fixture.

Device values: `browser`, `phone`, `visitor`, `player`, `admin`,
`second scorer`, `offline`, `slow`, `second browser`.

Not checkable by hand:

- **The "Live scoring is not enabled yet" refusal.** It appears only when the
  database migration has not been applied, and nothing in the app can un-apply
  it. Whether it can still be reached on the league's database is a question for
  whoever owns the migrations.
- **The inconsistent-games refusal.** It needs three completed games with no side
  on two wins, which normal play cannot produce and no screen can write.
- **Whether the browser's permission rule and the database's rule can disagree in
  any way other than the revoked-membership case in START-21.** They are separate
  mechanisms; comparing them properly means reading both, not using either.

Not checkable by hand:

- **Forcing the partial write in SETUP-18 reliably.** It needs the game write to
  succeed and the player write to fail, which means cutting the connection inside

- **Whether scorers understand the bags question, or answer it at random to get
  past it.** That needs watching real scorers on a league night, not a checklist.
  It is the question that decides whether the bag statistics on the review screen
  mean anything.
- **Provoking the server's validation rules.** The grids offer only valid
  combinations, so reaching "Round scores must be 0-12" or "Bag breakdown does not
  match the round score" needs a request built by hand. ROUND-28 records only
  whether the screen can produce them.
- **How fast the loop needs to be.** ROUND-33 measures what it is; whether that is
  fast enough between throws is a judgement about the venue and the league.
